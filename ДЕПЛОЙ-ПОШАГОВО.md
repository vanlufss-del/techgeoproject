# Выкладываем сайт: GitHub → Vercel → домены

Репозиторий уже готов: инициализирован, первый коммит сделан, 160 файлов. Ключей и паролей в нём нет — `.env` закрыт в `.gitignore`, в репозиторий попал только `.env.example` с пустыми заглушками.

Ниже — только те шаги, где нужен вход в твои аккаунты. Каждый занимает пару минут.

---

## Шаг 1. Пустой репозиторий на GitHub

1. **github.com** → **New repository**
2. Имя: `techgeoproject`
3. Видимость: **Private**
4. **Ничего не добавлять** — ни README, ни `.gitignore`, ни лицензию. Все галочки снять. Если добавить, репозиторий получит свой коммит и при первой отправке возникнет конфликт
5. **Create repository**

На открывшейся странице будет строка вида `https://github.com/ТВОЙ_ЛОГИН/techgeoproject.git` — она понадобится дальше.

---

## Шаг 2. Отправить код

Открой **PowerShell** в папке проекта. Проще всего: зайти в `techgeoproject`, щёлкнуть правой кнопкой по пустому месту → «Открыть в терминале».

Проверь, что git видит твоё авторство. Я проставил временные значения, замени на свои:

```powershell
git config user.name "Ivan"
git config user.email "почта_от_GitHub@example.com"
```

Почта должна совпадать с той, что указана в профиле GitHub — иначе коммиты не привяжутся к твоему аккаунту.

Дальше:

```powershell
git remote add origin https://github.com/ТВОЙ_ЛОГИН/techgeoproject.git
git push -u origin main
```

При первом запуске откроется окно входа GitHub — авторизуйся через браузер. Пароль в терминал вводить не нужно, GitHub его давно не принимает.

**Если ругается** `remote origin already exists` — значит адрес уже прописан, замени командой:

```powershell
git remote set-url origin https://github.com/ТВОЙ_ЛОГИН/techgeoproject.git
```

---

## Шаг 3. Проект в Vercel

1. **vercel.com** → **Add New** → **Project**
2. **Import Git Repository** → выбрать `techgeoproject`. Если репозитория нет в списке, нажать **Adjust GitHub App Permissions** и дать доступ
3. Настройки Vercel определит сам: Framework `Next.js`, команды по умолчанию. Менять ничего не нужно
4. Развернуть блок **Environment Variables** и добавить:

| Name | Value |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | `https://tehgeoproekt.ru` |
| `LEAD_TO_EMAIL` | `tehgeoproekt@mail.ru` |
| `LEAD_FROM_EMAIL` | `Сайт ТехГеоПроект <zayavka@tehgeoproekt.ru>` |

`RESEND_API_KEY` и `NEXT_PUBLIC_METRIKA_ID` добавим после регистрации в Resend и Метрике — без них сайт работает, просто заявки пишутся в лог, а счётчика нет.

5. **Deploy**

Через полторы-две минуты появится адрес вида `techgeoproject.vercel.app`. Сайт уже открывается — на нём можно всё проверить до подключения домена.

---

## Шаг 4. Домены

В проекте: **Settings** → **Domains**.

**Основной.** Добавить `tehgeoproekt.ru`. Vercel покажет, какие записи нужны в DNS.

Проще всего в панели Рег.ру сменить NS-серверы на `ns1.vercel-dns.com` и `ns2.vercel-dns.com` — тогда всеми записями управляет Vercel, и DNS для почты тоже настраивается там же, в одном месте.

Обновление NS занимает от 15 минут до нескольких часов. Пока не обновилось, Vercel будет показывать домен как `Invalid Configuration` — это нормально, нужно подождать.

**Редиректы.** Добавить туда же и указать перенаправление на `tehgeoproekt.ru`:

- `www.tehgeoproekt.ru`
- `tehgeoproject.ru` и `www.tehgeoproject.ru`
- `tehgeoproekt.online`
- `tehgeoproject.online`

Vercel при добавлении домена сам предлагает «Redirect to tehgeoproekt.ru» — согласиться. Тип перенаправления должен быть **307/308 или 301**, то есть постоянный: тогда поисковики передают вес основному домену, а не считают пять сайтов с одинаковым содержимым.

Для каждого из трёх дополнительных доменов NS тоже переключить на Vercel.

**HTTPS** выпустится автоматически, ничего делать не нужно.

---

## Шаг 5. Почта заявок и аналитика

По инструкции `ЗАПУСК-ТЕХНИЧКА.md`: Resend, записи SPF/DKIM/DMARC, счётчик Метрики. Записи вносятся в DNS уже на стороне Vercel, раз NS переключены туда.

После добавления `RESEND_API_KEY` и `NEXT_PUBLIC_METRIKA_ID` нужно нажать **Redeploy** — переменные с префиксом `NEXT_PUBLIC_` вшиваются в сборку, перезапуска мало.

---

## Что дальше происходит само

После подключения репозитория Vercel следит за веткой `main`. Любая правка, отправленная в GitHub, автоматически пересобирается и выходит на сайт за полторы минуты. Откатиться на любую прошлую версию можно одной кнопкой в разделе **Deployments**.

---

## Порядок, если коротко

1. Создать пустой приватный репозиторий на GitHub
2. `git remote add origin ...` и `git push -u origin main`
3. Импортировать репозиторий в Vercel, добавить три переменные, нажать Deploy
4. Проверить сайт на адресе `*.vercel.app`
5. Подключить домены, переключить NS в Рег.ру
6. Resend и Метрика, затем Redeploy
